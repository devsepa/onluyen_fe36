# Shared AI scheduling and deck preparation

Fresh `/v1/answers` work passes through one `AIWorkQueue` Durable Object. Shared explanation cache hits bypass it. The queue serializes provider calls, prioritizes active study over background work, and keeps only scheduling counters in durable storage. It does not store user prompts or images. Default spacing is 15 seconds for text and 60 seconds for images; waiting HTTP work is bounded. Provider 429 responses set a shared persisted cooldown, honoring the provider delay and increasing the wait after repeated limits. `GLOBAL_DAILY_QUESTIONS` caps fresh scheduled questions; cached explanations do not consume this allowance.

When `PREPARE_PUBLIC_DECKS=true`, the minute cron discovers published decks from the existing `DATA_API_BASE`. One `DeckPreparation` object per deck snapshots public question metadata and processes one question per alarm, normally one minute apart. Original image bytes are read when required, passed through the same explanation cache as study requests, and never stored in the preparation job. Cursor and counters survive tab closure and object restarts. Already prepared questions reuse the shared cache. Uncertain or conflicting answers are counted separately; original question-bank answers are never modified. Ordinary failures are retried at most three times per question; 429 waits without advancing the cursor. Deleted sources pause the job.

`GET /v1/preparation` returns public progress. `POST /v1/preparation/:deckId/start` and `/pause` require the existing verified moderator identity. In the account menu, moderators can open **Chuẩn bị giải thích bộ đề** to refresh progress and pause/resume jobs. Discovery does not resume a job paused by its owner. Private imports are not uploaded or included in the background preparation scan.

The deployed configuration adds migrations and bindings for `AIWorkQueue` and `DeckPreparation`; preserve all previous migrations and data bindings. AI remains on its own Worker while shared decks stay on the original storage endpoint. No API key is shipped to visitors. Raising provider quotas or billing is not part of this feature.

Validation: `node --test tests/*.test.mjs`; `node scripts/browser-preparation-qa.mjs` uses an isolated browser on port 9230 and synthetic API responses. The browser check covers public progress, guest restrictions, moderator pause/resume, and desktop/mobile in both themes.
