# Retry limits replace automatic advancement

Automatic question advancement and its controls were removed. The previous stored auto-advance preference has no effect. Manual next/previous, keyboard navigation and swipe navigation remain explicit actions.

Practice setup offers zero to five wrong attempts that can be retried; the default is two. This means the first two wrong submissions do not reveal the answer, and the third wrong submission reveals and locks it. Correct submissions reveal immediately. Zero preserves immediate grading after the first wrong submission. The setting is copied into each new practice session. Current restored practice sessions without a valid limit receive the saved/default preference. Wrong submissions and draft selections persist per question across navigation and reload.

Single-answer clicks submit an attempt. Multi-answer clicks only change a draft; an attempt is counted on the explicit Check/Enter action, with exact-set scoring. Pending retry feedback contains no correct answer, explanation, AI tutor or correct-choice styling. Study mistakes can play the existing wrong-feedback sound only on submission. Once finalized, answer buttons lock and explanations/reporting become available. All questions stay in place until explicit navigation. Mock exams remain editable and never reveal correctness before submission. Finishing a practice session includes the last pending wrong submission in the saved result, and result cards show the number of wrong attempts. A corrected answer after retries is scored by its final answer, with the attempt history retained.

Validation: 162 Node tests. Isolated Chrome (port 9225, `outputs/attempt-qa`) covers the third-wrong boundary, correct-first/after-retry, zero/one retry settings, single/multiple answers, empty checks, restore/navigation, legacy auto-advance enabled with no movement after 5.5 seconds, mock-exam isolation, partial submission, and sixteen desktop/mobile/landscape light/dark states. Synthetic slides and speaker explanations are used; no real user storage is cleared. Screenshots are under ignored `outputs/attempts/`.
