# Anonymous explanations and shared persistence

Study explanations do not require Google sign-in. Google is still required to read a private Google Slides source or synchronize a private library; published decks and restored original images can be used by guests.

There are two cache layers: the existing browser/bank cache saves structured explanations locally; the new `EXPLANATION_CACHE` Durable Object stores server-generated, validated explanations for later visitors. It has no automatic expiry. It is addressed by a SHA-256 fingerprint of the original image bytes, or exact text and ordered options, plus model and prompt revision. Source-specific ids, selected choices, answer keys, Google tokens, and original image bytes are not persisted. Different models, prompt revisions, images, or text do not share stale results. Simultaneous requests for one fingerprint share a generation. Results are returned using each caller's original id.

Only answered, complete explanations are retained. Uncertain/error results are not cached. Clients cannot submit a ready-made explanation to this cache. Text-based results must preserve every original choice; the frontend still rejects an answer that conflicts with the saved answer key. This verifies structure and agreement, not factual correctness. Cached responses retain their AI-origin disclosure.

The prompt emphasizes the question's actual task, negation, conditions, single/multiple answers, and per-option reasons. Keyword-based canned memory tips were removed; tips are shown only when present in the question's own saved explanation or tip fields. Earlier short Gemini import summaries no longer prevent full structured explanations from being requested. Original speaker/manual notes retain precedence.

The shared cache starts filling from requests made after deployment. Previously local explanations are not silently promoted to trusted server entries; no full-bank pre-generation is performed. The first uncached visitor may still wait for AI. The UI distinguishes local saving from a shared-cache hit.

Validation: 144 Node tests, including anonymous Worker requests from two simulated users, one upstream generation, Durable Object restart persistence, simultaneous deduplication, key invalidation, uncertain-result exclusion, and changed-choice rejection. Isolated Chrome tests verify anonymous requests without credentials/answer keys, local persistence and reuse, upgrading old AI summaries, shared-cache labels, and eight desktop/mobile/theme layouts. The post-deployment smoke sends a synthetic SQL question anonymously twice and asserts that the second response is reused. No real user's bank is modified. The existing sound test was updated to call the current `toggleSound` API; audio behavior is unchanged by this task.
