# Resource-saving changes

The account menu has a persisted Resource Saving control. It defaults on for coarse-pointer/mobile devices, Data Saver connections, or reduced-motion preference; an explicit user choice takes precedence. Original slide bytes and durable bank/backup/private-library images are not downscaled or deleted.

- Object URL retention drops from 300 images to 8 in economy mode or 24 normally. Neighbors are loaded only after the current slide, one/two ahead. The initial six-image burst and previous-slide decoding were removed. Prefetch warms bytes without decoding a hidden Image. Border detection is reused in a bounded 32-entry memory cache.
- Shared-deck view/AI image reads use the same pending request and a persistent temporary cache. It is separate from durable archives, capped at 8/24 MB with a seven-day TTL, and pruned when the budget is lowered. The source backend identity is included in hashed cache keys. Cache denial does not prevent ordinary network use.
- Review/library pictures are observed near the viewport, with two loads in flight at most; offscreen image nodes are removed and restored from the local temporary cache when needed. Text remains in place, with browser content-visibility to avoid painting every offscreen card. Text-only questions do not request images.
- Economy mode prepares AI only for the current question rather than three. Hidden tabs do not begin additional image or AI-prefetch jobs. Already running explanations are allowed to finish and save, avoiding wasted re-requests. Untimed study no longer rewrites progress every second; exam timers remain deadline-based and schedule one deadline wake-up when hidden.
- Expensive transitions, animations and backdrop filters are disabled in economy mode. The favicon reuses the existing 16.9 KB logo rather than downloading a separate 126 KB PNG.
- The service worker caches the actual relative module graph and versioned styles, uses cache-first for immutable versioned assets, and caps temporary application files at 96 entries per release while keeping at most two releases. Version-check URLs are not cached. Activation deletes only old application caches, preserving public/private image stores. Navigation's offline fallback awaits the actual cached response. Cache quota failure never discards a successful online response. Deployment stamps the worker with the release id; requests for updates are not served a stale version manifest.

Validation: 176 Node tests, including cache bounds/pruning, shared pending loads, persistent reuse, paused AI jobs, selective cache deletion, immutable file reuse, offline fallback, response/quota failure handling, and release stamping. Isolated Chrome (`outputs/resource-qa`, port 9226) measured two initial image fetches and one AI preparation for a 200-question fixture in economy mode, zero image refetches after reload, eight retained object URLs, no idle study progress mutations, crop reuse, hidden-tab prefetch pause, and lazy/offscreen results images. It verifies desktop/mobile light/dark controls, preserves a private-cache sentinel and an IndexedDB original through service-worker installation, and boots an actual study session offline with that original. The retry-limit suite also passes sixteen desktop/mobile/theme layouts. Service registrations/cache resets are limited to the isolated QA profile. Physical phone temperatures, battery consumption, and production bandwidth savings were not measured; the figures above are synthetic request/resource counts, not a thermal benchmark. Initial downloads, imports/OCR, and uncached questions still require work/network.
